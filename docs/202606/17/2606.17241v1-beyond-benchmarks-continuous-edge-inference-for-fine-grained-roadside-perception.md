## 摘要
在资源受限的边缘硬件上进行持续AI推理会引入传统基准评估难以察觉的部署效应，包括流视频的时间不稳定性、持续负载下的热节流以及依赖于工作负载的性能变异性。我们提出了Edge-TSR，一个面向部署的持续边缘推理系统，用于NVIDIA Jetson Orin Nano上的持续路边感知。Edge-TSR集成了检测、跟踪、细粒度分类以及一种轻量级的轨迹感知时间稳定机制，可在计算开销可忽略的情况下提高流推理一致性。我们的核心发现是，以基准为中心的评估系统地高估了已部署的边缘推理性能。在三个最先进的基线上，我们观察到从静态图像评估过渡到真实世界流部署时，一致出现20-30%的相对性能下降。Edge-TSR通过时间推理稳定弥补了这一差距，相较于逐帧推理基线，恢复了高达10.16%的分类准确率，同时在持续运行中保持实时性能。我们在多种真实部署条件下评估了整个系统，联合描述了长时间运行期间的推理质量、延迟、吞吐量和热行为。在一次26公里路线上的55分钟车载部署中，单个嵌入式设备在安全热限制内以16.18 FPS持续运行，无需云端卸载。我们的发现表明，面向部署的评估和时间推理稳定是面向真实世界传感部署的持续运行边缘AI系统的必要组成部分。我们发布了一个带注释的流视频评估数据集样本和完整的系统实现，以支持可重复的部署中心评估。

## Abstract
Continuous AI inference on resource-constrained edge hardware introduces deployment effects that are largely invisible to conventional benchmark evaluation, including temporal instability in streaming video, thermal throttling under sustained load, and workload-dependent performance variability. We present Edge-TSR, a deployment-oriented continuous edge inference system for sustained roadside perception on the NVIDIA Jetson Orin Nano. Edge-TSR integrates detection, tracking, fine-grained classification, and a lightweight track-aware temporal stabilization mechanism that improves streaming inference consistency with negligible computational overhead. Our central finding is that benchmark-centric evaluation systematically overstates deployed edge inference performance. Across three state-of-the-art baselines, we observe consistent 20-30% relative degradation when transitioning from static-image evaluation to real-world streaming deployment. Edge-TSR addresses this gap through temporal inference stabilization, recovering up to 10.16% classification accuracy over per-frame inference baselines while maintaining sustained real-time performance under continuous operation. We evaluate the complete system under diverse real-world deployment conditions, jointly characterizing inference quality, latency, throughput, and thermal behavior during long-duration operation. A 55-minute vehicular deployment over a 26 km route demonstrates sustained operation at 16.18 FPS within safe thermal limits on a single embedded device without cloud offload. Our findings show that deployment-aware evaluation and temporal inference stabilization are necessary components of continuously operating edge AI systems intended for real-world sensing deployments. We release a sample annotated streaming video evaluation dataset and full system implementation to support reproducible deployment-centric evaluation.

## 1. 核心问题与整体含义

*   **研究动机**：当前边缘AI系统在真实世界部署时面临三大“部署效应”，而这些效应在传统的、静态的基准评测中完全不可见：
    *   **时间不稳定性**：流式视频帧间的运动模糊、遮挡、光照变化会导致模型预测在帧间频繁抖动。
    *   **热节流**：持续的高负载推理会使嵌入式硬件升温，触发降频，导致性能非线性下降。
    *   **工作负载波动**：场景复杂度的变化会直接导致推理延迟和吞吐量的波动。
*   **核心问题**：基于静态图像的基准评测会**系统性高估**边缘AI系统的实际部署性能，造成“实验室表现优异、现场表现不佳”的失败模式。现有研究大多孤立地解决单个问题，缺乏在真实部署环境下对上述所有挑战的联合评估。
*   **整体含义**：论文以“交通标志识别”为具体用例，揭示了基准评测与真实部署之间存在约**20-30%** 的性能差距，并指出**部署感知评估**和**时间推理稳定化**是任何持续运行边缘AI系统的必要设计原则。

## 2. 提出的方法论：Edge-TSR

*   **核心思想**：设计一个面向部署的持续边缘推理系统，将**时间一致性**和**部署可持续性**作为一等公民的系统目标，而非次要的评估产物。
*   **关键技术细节与流程**：
    *   **四阶段流水线**：
        1.  **稀疏帧采样器**：每 `k=3` 帧才执行一次完整的检测推理，其余帧通过跟踪状态传播来减少计算开销和热积累。
        2.  **检测与跟踪**：使用**类无关**的YOLOv8检测器定位所有候选标志区域，并使用**ByteTrack**跟踪器将跨帧的检测结果关联起来，赋予持久身份（ID）。
        3.  **细粒度分类**：仅在检测到的区域（RoI）上执行ResNet-50分类器，将计算成本与场景中的活动目标数量挂钩，并对输入进行上下文的扩充和几何修剪。
        4.  **轨迹感知时间稳定层**：这是一个核心创新，旨在抑制帧间标签的闪烁。
    *   **时间稳定机制**：
        *   **记忆缓冲**：为每个轨迹维护一个长度为 `T=5` 的滑动窗口，存储历史预测标签和置信度。
        *   **置信度加权多数投票**：对窗口内的预测进行加权聚合，奖励“出现频率高”且“置信度高”的类，惩罚不确定的预测。
        *   **滞后锁定状态机**：一个两状态机，包括候选状态和锁定状态。当一个标签满足`出现次数 >= 3`且平均置信度`> 60%`时，从候选状态**锁定**；被锁定的标签不会因单帧噪声而改变。只有当新的候选标签提供足够强且有持续的证据（出现次数多、置信度超过当前锁定标签一定阈值）时，锁定的标签才会被**解锁**（释放条件）。对“未知”类别有更宽松的解锁规则。
*   **算法流程**：采样帧 → YOLOv8检测 → ByteTrack跟踪 → 区域预处理 → ResNet-50分类 → 稳定模块（置信度投票 + 滞后锁定） → 输出稳定标签。在非采样帧，仅通过卡尔曼滤波传播跟踪状态和上次稳定标签。

## 3. 实验设计

*   **数据集**：
    *   **训练集**：**INTSD**（印度夜间交通标志数据集），包含41个类别、14044个实例，其视觉噪声特征与部署场景匹配。
    *   **评估集**：作者自行录制并标注的**流视频评估数据集**，包含**50,732帧**，涵盖四种对系统进行压力测试的真实场景：
        1.  **密集城市交通**：高密度、高计算负载。
        2.  **雨天**：检测器置信度受压制。
        3.  **乡村/黑暗**（无路灯）：极端的夜间检测挑战。
        4.  **分布外**：包含非标准形式或全新类别的标志，测试系统在封闭世界假设下的行为边界。
*   **基准与对比方法**：
    *   **对比基线**：YOLO-LLTS、YOLO-TS、LENS-Net（均为近期TSR领域的方法，在INTSD上训练）。
    *   **评估协议**：同时进行**基于图像**（INTSD）和**基于流视频**（自录数据集）的评估，以量化“部署差距”。
    *   **评估指标**：包括系统级（FPS，组件延迟，功耗，热效应）、时间一致性（标签翻转率）、检测（mAP@50, mAP@50:95）和分类（宏观精度A.P.，宏观召回A.R.，准确率Acc.）四类。

## 4. 资源与算力

*   **硬件平台**：**NVIDIA Jetson Orin Nano**（8 GB统一内存版本，7-25W可配置功耗），这是一款典型的资源受限边缘设备。
*   **算力与优化**：模型使用FP32精度，**未使用TensorRT优化**，这建立了一个“开箱即用”的性能基线，而非硬件特定的最佳性能。训练在INTSD的Fold 0上完成，但论文**未明确说明训练阶段使用的GPU型号、数量和训练时长**。

## 5. 实验数量与充分性

*   **实验数量**：实验设计较为充分，包括：
    1.  **全量对比**：与三种基线方法在图像和视频两种协议下的性能对比。
    2.  **跨场景评估**：在四种真实场景下的系统性能表现。
    3.  **稀疏采样消融**：对比不同采样间隔（k=1, 3, 5, 10, 30）对性能、延迟、热效应的影响。
    4.  **稳定模块消融**：通过去除记忆、投票、滞后锁定等组件，隔离每个部分的贡献。
    5.  **骨干网络对比**：比较MobileNetV3、EfficientNet-B3和ResNet-50。

    *   **充分性**：实验覆盖了系统性能的多个维度（准确率、吞吐量、热效应、时间稳定性）和多种真实环境，能够有力地支持其核心论点。
    *   **公平性**：对比基线在相同的Jetson Orin Nano硬件上运行，确保了系统级指标的可比性。所有场景均使用同一套固定配置，避免了“定制化”调优带来的偏差。消融实验设计干净，有效地揭示了每个组件的核心贡献。

## 6. 主要结论与发现

1.  **基准评测高估性能**：在从静态图像评估转向流视频评估时，所有基线系统性能均一致下降**20-30%**，证明部署差距是真实且普遍存在的。
2.  **时间稳定至关重要**：在所提出的稳定模块中，**滞后锁定**对提升分类准确率的贡献最大（**10.16%**），并能大幅降低标签翻转率，验证了其核心设计动机。
3.  **检测与分类瓶颈各异**：在夜间/黑暗场景中，性能瓶颈主要在**检测器**（无法定位到标志），而非分类器。这使得系统优化的方向更加明确。
4.  **最优采样间隔**：`k=3`是最优采样间隔。它能在不引入过多计算开销的同时，通过时间稳定机制最大化F1分数，并在延迟和热控之间取得最佳平衡。
5.  **负载相关吞吐量**：在更恶劣的条件下（如雨天），由于检测到的目标更少，系统吞吐量反而增高，形成了“吞吐量-准确率反转”现象。
6.  **组件基准不是部署目标**：在55分钟实地部署中，检测器延迟几乎翻倍（34.96ms → 65.68ms），表明组件级基准仅为上限，实际部署需为系统开销预留余量。

## 7. 优点

*   **方法论创新**：明确提出并量化了“部署差距”这一关键问题，并将部署可持续性作为系统设计的核心目标，而非事后分析。
*   **轻量级稳定机制**：提出的时间稳定模块（滑动窗口+多数投票+滞后锁定）计算开销极低（O(T)），但在抑制帧间抖动和提升准确率方面效果显著，非常适合资源受限设备。
*   **全面的系统级表征**：不仅关注识别准确率，还系统性地分析了延迟、吞吐量、内存压力、热效应等部署关键指标，形成了对边缘AI系统行为的完整画像。
*   **实用性强**：研究基于真实世界的行驶数据录制和长达55分钟的车载部署验证，提供了大量关于系统在实际环境中行为的宝贵见解。
*   **开源贡献**：公开了完整的系统实现和评估数据集，有助于推动该领域的可重复研究。

## 8. 不足与局限

1.  **封闭世界分类器**：分类器是41类的固定词汇表，无法可靠地对未见过的交通标志类别进行“我不知道”的识别，导致对分布外样本产生高置信度的错误分类（如将装饰牌错判为“方向”标志）。
2.  **固定采样策略**：采样间隔（k=3）是静态的，未能根据车速、场景复杂度或温度动态调整。在高速行驶时，帧与帧间的位移大，可能导致跟踪漂移和时间窗口饥饿（不够观察次数累计）。
3.  **地理范围有限**：训练和评估数据都来自印度，结论的泛化性可能受限于道路结构、标志设计和驾驶环境。
4.  **单模态感知**：仅依赖单目RGB摄像头，在光照、天气等极端条件下存在固有的脆弱性。融合红外、雷达等多模态信息可能会提升系统鲁棒性，但会增加复杂性。
5.  **未使用TensorRT**：作者明确指出未使用硬件特定的推理优化，导致推理效率可能低于峰值，这在一定程度上低估了系统在优化后的吞吐量。
6.  **超参数经验性设置**：时间模块中的锁定阈值（T=5, 置信度>60%等）是经验性选择的，可能在不同场景下并非最优，缺乏自适应性。
