## 摘要
尽管视频大语言模型（Video-LLMs）取得了显著进步，但当前的在线架构仍然难以同时处理连续视频流、自主决定何时响应以及保持长时上下文记忆。这些障碍损害了实时响应能力，并导致长时间交互中的严重遗忘。在这项工作中，我们介绍了LiveStarPro，一个专为长时长流式视频主动理解设计的直播助手。LiveStarPro的设计基于三个互补组件。第一个组件是流验证解码（SVeD），一个通过单遍困惑度验证来确定适当响应时机的推理框架，从而消除对显式静默标记的依赖。第二个组件是流因果注意力掩码（SCAM），一种训练策略，强制在可变长度流上进行增量式视频-语言对齐。第三个组件是树状分层记忆（TSHM），一种递归记忆架构，将驱逐的历史信息组织成事件链，从而能够从有效无界的视频流中进行高效检索。为了在真实在线条件下促进全面评估，我们进一步提出了OmniStarPro，一个涵盖15种多样化真实世界场景的大规模基准，并扩展至小时级流以评估长期回忆。大量实验表明，LiveStarPro持续超越现有方法，在语义正确性上提升28.9%，时序误差减少18.2%，同时其流键值缓存相比无缓存的相同模型实现了1.58倍的推理加速。模型和代码已公开在 https://github.com/sotayang/LiveStarPro。

## Abstract
Despite the remarkable progress of Video Large Language Models (Video-LLMs), current online architectures still struggle to simultaneously process continuous video streams, decide autonomously when to respond, and preserve long-horizon contextual memory. These obstacles undermine real-time responsiveness and cause severe forgetting throughout prolonged interactions. In this work, we introduce LiveStarPro, a live streaming assistant that is designed for proactive video understanding over long-horizon streams. The design of LiveStarPro rests on three complementary components. The first component is Streaming Verification Decoding (SVeD), an inference framework that identifies the appropriate response timing through single-pass perplexity verification, thereby eliminating the dependency on explicit silence tokens. The second component is Streaming Causal Attention Masks (SCAM), a training strategy that enforces incremental video-language alignment over variable-length streams. The third component is Tree-Structured Hierarchical Memory (TSHM), a recursive memory architecture that organizes evicted historical information into event chains and consequently enables efficient retrieval from effectively unbounded video streams. To facilitate a comprehensive evaluation under realistic online conditions, we further present OmniStarPro, a large-scale benchmark that spans 15 diverse real-world scenarios and that extends to hour-scale streams for the assessment of long-term recall. Extensive experiments demonstrate that LiveStarPro consistently surpasses existing methods, attaining a 28.9% improvement in semantic correctness and an 18.2% reduction in timing error, while its streaming key-value cache further yields a 1.58x inference speedup over the same model without caching. The model and the code are publicly available at https://github.com/sotayang/LiveStarPro.

  2. **长程记忆保持**：简单的滑动窗口机制会导致上下文窗口饱和、灾难性遗忘以及无法检索已丢弃的历史信息，无法应对无界视频流中的长时推理。

### 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

#### 2.1 框架总览
LiveStarPro 由三个互补模块组成：**SVeD**（推理响应时机）、**SCAM**（训练对齐策略）、**TSHM**（层次化长期记忆），三者协同实现“先验证、后生成”的主动响应范式。

#### 2.2 Streaming Verification Decoding (SVeD)
- **核心思想**：将沉默决策从“预测”变为“验证”。不再让模型学习输出一个特殊的EOS标记，而是通过单次前向传播验证当前已有描述与最新视觉帧的语义一致性，从而决定是否生成新输出。
- **算法流程**：
  - 对于每个新帧，计算当前描述的解码困惑度（PPL）。
  - 若新PPL > α × 旧PPL（α为阈值），说明视觉变化显著，触发新描述生成；否则保持沉默，将当前描述逻辑“交换”到上下文末尾以表示时间流逝。
  - 采用流式KV缓存支持高效上下文更新，避免重复计算。

#### 2.3 Streaming Causal Attention Masks (SCAM)
- **核心思想**：训练时模拟流式推理的增量特性，强制模型在每一帧上基于当前视觉和历史上下文生成描述，而不是依赖前一帧的文本输出。
- **关键技术**：
  - 将数据组织成交错帧-描述序列，同一语义片段内的所有帧共享同一描述。
  - 使用随机采样从多个描述变体中选择，防止过拟合。
  - **SCAM掩码**：在同一语义片段内，屏蔽先前已生成的描述标记，迫使模型仅依赖视觉特征和外部历史上下文；跨片段保持正常因果注意力。

#### 2.4 Tree-Structured Hierarchical Memory (TSHM)
- **核心思想**：模拟人类认知的双层存储——短期工作记忆（高分辨率当前上下文）和长期检索记忆（结构化历史存储）。
- **短期工作记忆**：基于“峰值-结束”规则压缩。保留语义置信度高的关键帧（低PPL）和每个语义片段的摘要描述；当上下文超载时，逐段裁剪冗余帧（保留约50%）。
- **长期检索记忆**：递归事件树。每个节点包含事件描述、视觉标记、语义嵌入和子节点列表。新单元插入时，与现有节点计算相似度，若高于阈值则作为子节点；否则新建根节点。父节点嵌入通过动量聚合更新为子树语义中心。
- **检索过程**：层次化波束下降，从根节点开始逐层评估Top-k子节点，复杂度为O(k b log_b n)，预期亚线性。

### 8. 不足与局限

- **计算成本**：虽然推理速度有所提升，但3-4 FPS仍无法满足高帧率实时应用（如60 FPS直播），且全量微调需要8块A800。
- **阈值依赖**：SVeD的α需要根据域校准（最优范围窄），增加部署开销。TSHM的相似度阈值σ和动量β也需要仔细调节。
- **记忆结构假设**：递归事件树的有效性依赖于语义聚类假设，若流内容高度复杂或事件边界模糊，树结构可能退化（链式或扁平），检索效率下降。
- **实验覆盖**：
  - 长记忆评估仅基于OmniStarPro-Long，缺乏与其他长期视频记忆方法的直接对比（论文中仅使用扁平k-NN作为代理比较）。
  - 未在语音、多模态音频等场景上评估（当前仅处理视觉和文本）。
  - 离线基准（MVBench等）有轻微下降，表明流式训练可能牺牲部分全局推理能力。
- **偏差风险**：
  - 数据主要来自YouTube，可能存在平台和文化偏好。
  - 使用GPT-4o作为评分器可能引入风格偏差，虽未影响排名但绝对分数需谨慎解读。
- **应用限制**：当前版本静默成本主要是计算PPL，但若处理极快帧率仍需优化；树记忆的写入和检索操作会增加单次延迟。
