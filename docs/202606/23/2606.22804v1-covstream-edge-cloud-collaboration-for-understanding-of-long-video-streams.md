## 摘要
长时间连续视频流是多媒体智能日益关键的驱动力。现有工作通常采用大模型进行“采样-编码-推理”的方式来处理长视频，但忽略了一个关键的部署事实：视频流往往由计算受限的设备产生。这导致一个不可行的折衷：云端卸载虽然能实现强推理，但带来高昂的带宽开销；而设备端处理则受限于边缘硬件能力。为此，我们提出CoVStream，首个用于理解长视频流的边云协同框架。边缘节点将原始视频流提炼为紧凑的视觉特征和语义字幕传输至云端，最小化带宽成本；云端服务器将这些数据整合为实体图与全局视觉上下文，仅当用户查询到达时才激活重型推理模型。在VideoMME-Long、LVBench和RTV-Bench上的实验表明，CoVStream在LVBench上降低87.6%的带宽使用，同时保留云端基线99.2%的准确率。

## Abstract
Long, continuous video streams are an increasingly critical driver of multimedia intelligence. Existing efforts often handle long videos with a sample-encode-reason approach using large models. However, they overlook a crucial deployment fact: the stream is often produced by computationally constrained devices. This forces an untenable compromise: cloud offloading unlocks strong reasoning but incurs prohibitive bandwidth overhead, while on-device processing remains limited by edge hardware capacity. Therefore, we propose CoVStream, the first edge-cloud collaborative framework for understanding long video streams. The edge node distills raw video streams into compact visual features and semantic captions for transmission to the cloud, minimizing bandwidth costs, while the cloud server integrates this data into an entity graph and global visual context, activating the heavy reasoning model only when a user query arrives. Experiments on VideoMME-Long, LVBench, and RTV-Bench show that CoVStream reduces bandwidth usage by 87.6% while retaining 99.2% of the cloud baseline accuracy on LVBench.

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：长视频流理解面临“带宽-算力”两难困境。现有方法（sample-encode-reason）依赖大型多模态模型，要么将原始视频完全卸载到云端（Cloud-Only），导致巨大的传输带宽开销；要么在计算受限的边缘设备上本地处理（Local-Only），受硬件限制只能用轻量模型，推理性能严重下降。二者不可兼得。
- **背景**：AI眼镜等始终在线设备产生连续长视频流，需要记忆检索、事件回忆等任务。现有离线基准忽视了这一部署约束，亟需一种能平衡带宽、精度和延迟的端云协同方案。
- **整体含义**：本文提出首个适用于长视频流的边云协同框架 CoVStream，通过边缘端实时压缩语义信息、云端按需推理，在保持高精度的同时大幅降低带宽和内存占用，为实际持续部署提供可行路径。

## 2. 提出的方法论

### 核心思想
利用视频流中的时空冗余，边缘设备作为“语义压缩器”将原始帧转化为紧凑的视觉特征和文字描述，云端维护长期记忆（实体图+全局视觉上下文），仅在用户查询到来时激活大模型推理，实现“低带宽、高精度、低延迟”。

### 关键技术细节

#### 边缘端：双流感知与压缩流水线（Dual-Condensed Perception Pipeline）
- **视觉特征提取**：用轻量视觉编码器（0.4B，VideoLLaMA3-7B的视觉端）为每帧提取特征向量 \( f_t \in \mathbb{R}^{N \times d} \)，放入特征队列。
- **时间特征压缩**（Temporal Feature Condensation）：当特征缓冲区达到 \( N_{temp}=16 \) 帧时，迭代合并最相似相邻特征对（余弦相似度最大），直至压缩到预设数量 \( N_{target}=2 \)（压缩率87.5%）。
- **自适应关键帧选择**（Adaptive Keyframe Selection）：另一个缓冲区积累 \( N_w=64 \) 帧后，通过聚类（初始 k=⌊√Nw⌋）并最大化轮廓系数，选取靠近聚类中心的帧作为关键帧（数量 m ≪ 64）。
- **语义字幕生成**：对关键帧使用轻量语言模型（Qwen3-VL-2B-Instruct）生成简洁句子描述，强制“简单陈述句”规则。
- **硬件感知并行调度**：将视觉编码/字幕生成放在GPU，聚类/合并算法放在CPU，流水线处理，每帧平均耗时从64.98ms降至52.03ms，实现实时处理。

#### 云端：解耦的管理与推理架构
- **内存管理（持续运行）**：
  - 全局视觉上下文：接收压缩视觉特征 \( Z_{cond} \)，用迭代合并算法维护一个容量上限为 \( N_{bank}=128 \) 的压缩库，防止无限增长。
  - 实时实体图构建：每收到字幕文本，先进行语法解析成“主语-动词-宾语”三元组；通过NLI分类器（DeBERTa-v3）判断新实体与30秒窗口内候选实体的双向蕴含关系，相似则融合为同一节点；使用文本嵌入模型（Qwen3-Embedding-0.6B）将每个字幕向量化并挂载到对应节点上。
- **按需推理（休眠-唤醒机制）**：
  - 默认休眠；收到边缘触发后立即激活。
  - **查询向量化**：将用户查询 \( Q \) 用同一嵌入模型编码为向量 \( V_q \)。
  - **字幕检索**：计算 \( V_q \) 与各节点挂载字幕向量的余弦相似度，取 top-3 最相关的节点作为语义锚点。
  - **子图提取**：从锚点扩展一阶邻居，形成相关子图 \( G_{sub} \)。
  - **图序列化**：将子图序列化为 JSON 格式。
  - **最终推理**：将全局视觉上下文 \( H_t \)、序列化子图、原查询一起送入大模型（VideoLLaMA3-7B）生成回答 \( R \)。

整个框架无需训练（training-free），直接利用已有模型的原始特征空间，即插即用。

## 3. 实验设计

### 使用数据集/场景
- **VideoMME-Long**：6大视觉领域、30个子领域，平均时长 3160 秒，900 道单选题。
- **LVBench**：极长视频理解，选取超 2800 秒的子集（平均 5018 秒），共 1007 道单选题，侧重“大海捞针”式检索。
- **RTV-Bench**：实时视频流基准，167.2 小时流式视频，平均每段 1092 秒，覆盖自我中心智能、智能驾驶、体育分析等。

### 对比方法
- **Local-Only (LO)**：用轻量版 VideoLLaMA3-2B 在边缘本地处理，代表精度下限、带宽零成本。
- **Cloud-Only (CO)**：用 VideoLLaMA3-7B 在全采样帧（1 FPS）上云端推理，代表精度上限、最高带宽。
- **Edge-Cloud Hybrid (EC)**：边缘 1 FPS 采样并 4× 下采样后传输，云端用 AuraSR-v2 扩散模型超分辨率重建后再推理。

### 评估指标
准确率（Acc.）、通信量（Comm. MB）、压缩率（Comp.）、端到端延迟（Lat. s）。

## 6. 主要结论与发现

- **精度**：CoVStream 在 LVBench 上达到 CO 基线的 99.2%（38.93% vs 39.23%），在 VideoMME-Long 上保留 94.5%，远超 LO 和 EC。
- **带宽**：相对于 CO，平均降低 87.6% 的通信开销（从 2,550 MB 降至 316 MB）。
- **延迟**：端到端延迟 2.99 秒，低于 CO 的 4.08 秒，接近 LO 的 2.72 秒（得益于异步管理）。
- **超长视频鲁棒性**：视频长度 >6000 秒时，CoVStream 超过 CO 7.92%（42.92% vs 35.00%），说明结构图避免了 LLM 上下文窗口饱和问题。
- **内存可扩展性**：24 小时模拟后，云端内存仅 439 MB，相比基线 230 GB 降低 523 倍，可持续运行。
- **组件贡献**：实体图构建是精度提升关键（消融ID 6 vs ID 7：34.66%→38.93%），特征压缩和关键帧选择共同保证了带宽效率。

## 7. 优点

- **训练无需额外训练**：所有处理都在已有模型特征空间完成，即插即用，可适配多种 LMM。
- **端云协同解耦设计**：边缘专攻实时压缩，云端专攻长时记忆和按需推理，互不阻塞，延迟低。
- **双重压缩机制**（特征合并 + 关键帧筛选 + 语义字幕）极大降低带宽，且通过实体图补偿信息损失。
- **结构化的实体图**：支持基于查询的子图检索，避免无关信息干扰，提升长视频推理准确性。
- **内存可控**：固定容量压缩库 + 动态实体图，内存占用饱和，适合始终在线部署。
- **硬件感知流水线**：异构调度充分发挥边缘设备 GPU/CPU 能力，实现实时处理。

  - 压力测试的 GPU 型号最高为 A40（48 GB），未覆盖更常见的低功耗移动 GPU（如 Jetson 系列或手机 NPU），仅引用了 Jetson Thor 的 TFLOPS 数值作为参考，缺乏实际部署数据。

- **风险估计**：
  - 实体图构建依赖 NLI 分类器的双向蕴含判定，当实体表述高度模糊或同义表达不同（例如“a man in black suit”与“the guy wearing dark jacket”）时，可能产生错误融合或分裂，影响后续检索。
  - 字幕生成使用 2B 模型，在长视频中可能出现幻觉或重要信息遗漏（尤其快速动作场景），从而影响图的质量。
  - 延迟测量在固定网络条件下进行，未考虑真实环境下带宽波动或边缘计算负担变化。
- **应用限制**：
  - 当前仅验证选择题型（多项选择），对于开放式问答和生成式任务（如“描述整个事件”）仅附录中提及，缺乏系统报告。
  - 需要边缘设备具备 GPU 能力（至少 0.4B 编码器 + 2B 字幕模型），极低算力设备（如仅有 CPU 的传感器）可能无法运行实时流水线。
  - 云端需一直运行内存管理进程（虽然资源少，但仍有持续开销），若边缘节点数量多，云侧负载需进一步评估。
  - 隐私问题：语义描述和压缩特征仍包含场景信息，在隐私敏感场景下需额外加密或差分隐私保护。
