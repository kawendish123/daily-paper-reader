## 摘要
流式视频大语言模型必须持续处理输入的视频，同时保持低查询延迟，因此视频摄入吞吐量和查询时间响应性对于实时部署都至关重要。现有方法主要集中在加速单个模块上，如视觉编码、令牌剪枝或KV缓存压缩，但关于结果系统能否维持实时流式性能的见解有限。我们将流式视频大语言模型推理形式化为一个协调管道，涵盖视觉预处理、视觉编码、令牌丢弃和大语言模型预填充/解码。基于此形式化，我们提出了ViCoStream（视频协调流式处理），一个分阶段协调的流式框架，结合了分块执行、CUDA流重叠、视觉令牌控制、有界视觉注意力和查询端检索，以限制每块的计算和内存成本。我们进一步提供了瓶颈迁移的系统研究，揭示了块大小、令牌保留、注意力局部性和检索范围如何影响吞吐量-准确率权衡。在多个流式基准测试上使用Qwen2.5-VL-3B/7B-Instruct进行的实验表明，ViCoStream在单个A100 GPU上实现了134 FPS的视频吞吐量和小于50 ms的TTFT，同时保持了接近全历史基线的准确率。

## Abstract
Streaming VideoLLMs must continuously process incoming video while maintaining low query latency, making both video-ingestion throughput and query-time responsiveness critical for real-time deployment. Existing methods largely focus on accelerating individual modules, such as visual encoding, token pruning, or KV-cache compression, but provide limited insight into whether the resulting system can sustain real-time streaming performance. We formulate streaming VideoLLM inference as a coordinated pipeline spanning visual preprocessing, visual encoding, token dropping, and LLM prefilling/decoding. Building on this formulation, we propose ViCoStream (Video Coordinated Streaming), a stage-wise coordinated streaming framework that combines chunk-wise execution, CUDA-stream overlap, visual token control, bounded visual attention, and query-side retrieval to bound per-chunk computation and memory costs. We further provide a systematic study of bottleneck migration, revealing how chunk size, token retention, attention locality, and retrieval scope shape the throughput-accuracy trade-off. Experiments with Qwen2.5-VL-3B/7B-Instruct across multiple streaming benchmarks show that ViCoStream achieves 134 FPS video throughput and less than 50 ms TTFT on a single A100 GPU while maintaining accuracy close to full-history baselines.

## 1. 核心问题与整体含义（研究动机和背景）

流式视频大语言模型（Streaming VideoLLMs）需要持续处理不断到来的视频帧，同时保持对用户查询的低延迟响应。现有方法大多集中于优化单个模块（如视觉编码加速、令牌剪枝、KV缓存压缩），但缺乏对系统整体实时流式性能的系统建模与分析。作者指出，即使某个模块被加速，瓶颈可能只是转移到另一个阶段，导致整体吞吐量仍无法满足实时要求。例如，令牌丢弃可以减少LLM计算量，但若可见视觉历史不断累积，预填充延迟仍会随流长度增长（图1）。因此，本文的核心动机是：**将流式视频LLM推理视为一个多阶段协调流水线，通过识别和控制各阶段瓶颈，联合优化视频摄入吞吐量与查询时间首令牌延迟（TTFT）**。

## 2. 方法论：核心思想、关键技术细节

ViCoStream 将流式推理组织为四个连续阶段（视觉预处理 → 视觉编码 → 令牌丢弃 → LLM预填充/解码），并引入以下关键技术：

- **分块执行（Chunk-wise Execution）**：将视频流划分为非重叠的块（chunk），每个块包含 c 帧，以利用ViT编码器的批量处理效率。块大小 c 可调，影响各阶段延迟和整体吞吐量。
- **CUDA流重叠（CUDA-stream Overlap）**：视觉预处理阶段使用独立CUDA流，使其与后续模型阶段重叠执行，避免预处理延迟被串行化。
- **视觉令牌控制（Visual Token Control）**：
  - **空间压缩**：在帧级别通过平均池化、最大池化或基于熵的选择，将每个帧的令牌数从 n_f 压缩到 \bar{n}_f。
  - **时间压缩**：在块级别计算帧间空间位置对应令牌的余弦相似度，若所有帧对的相似度均超过阈值 τ，则丢弃该位置令牌，并始终保留每个块的第一个帧作为锚点。
- **有界视觉注意力（Bounded Visual Attention）**：LLM预填充时，每个新视觉块仅能关注最近的 acn 个历史块，限制可见缓存大小，使预填充延迟不再随流长度增长。
- **查询端检索（Query-side Retrieval）**：用户查询时，通过查询令牌平均特征与各视觉块平均特征的余弦相似度，检索 top-k 个最相关的视觉块，仅对这些块进行注意力计算，进一步限制查询时视觉上下文。
- **自适应训练掩码（Adaptive Training Mask）**：在训练阶段构造附加注意力掩码，使视觉令牌只能访问最近 acn 个块（阶梯状局部带），查询令牌只能访问检索出的块（稀疏非连续），以对齐训练与推理时的可见模式。

流水线吞吐量由最慢阶段决定：`T_pipe = max{T_vp, T_vit, T_drop, T_llm}`，最大帧率 `FPS_max = 1000*c / T_pipe`。

## 6. 主要结论与发现

- ViCoStream 通过阶段协调流水线，在单A100 GPU上实现了高达 **134 FPS** 的视频摄入吞吐量，且查询TTFT低于 **50 ms**。
- 令牌丢弃率在中等水平（如30%保留）时，准确率接近全历史基线（差距通常在3个百分点以内）；更激进丢弃（10%保留）会导致部分任务退化，尤其是对细粒度计数和文本丰富场景敏感。
- 视觉注意力局部性（acn=4左右）和查询检索预算（ur=32左右）能够有效控制LLM预填充成本，且不会显著损害大多数任务的准确率。
- **瓶颈迁移现象**：当LLM侧成本被压缩后，瓶颈会向视觉编码或视觉预处理阶段转移，因此需要全局协调而非单模块优化。
- 时间维度的令牌冗余比空间冗余更安全地可丢弃；空间压缩需谨慎选择策略（熵选择优于平均/最大池化）；两者组合会累积损失。

## 7. 优点

- **系统级视角**：将流式推理视为多阶段流水线，而非孤立模块优化，揭示了瓶颈迁移这一关键现象，为高吞吐流式系统设计提供了统一框架。
- **实用性控制**：结合分块执行、CUDA流重叠、有界注意力、查询检索等轻量级技术，无需修改模型架构，即可显著提升吞吐量且保持准确率。
- **实验充分**：在多个流式基准上进行了大量消融，覆盖不同骨干、不同压缩配置、不同注意力范围，并提供了详尽的延迟与吞吐量数据，结果可信度高。
