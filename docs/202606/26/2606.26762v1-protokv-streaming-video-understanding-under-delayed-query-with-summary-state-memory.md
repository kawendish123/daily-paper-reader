## 摘要
流式视频理解（SVU）必须在严格的GPU内存和查询时间延迟预算下，在视觉标记连续流式传输的同时，回答异步到达的查询。一个关键挑战是延迟查询：决定性的线索可能短暂出现，但在查询到达前会发生许多后续更新，从而增加了这些线索在有界内存下被驱逐或稀释的风险。我们提出ProtoKV，一种恒定足迹的SVU记忆，它将远距离历史表示为固定容量的摘要状态，而不是保留标记实例。ProtoKV保留精确的近窗口KV缓存，并将较旧的内容聚合到具有残差统计的语义-空间原型库中。在查询时，每个原型通过一个有界的伪标记接口暴露，该接口可与标准注意力机制即插即用。在匹配的预算和可比较的查询时间成本下，ProtoKV在长延迟情况下，在SVU基准测试中的准确率比标记保留基线提高了多达12.5个百分点，且随着查询延迟的增加，增益也会增大。

## Abstract
Streaming video understanding (SVU) must answer queries that arrive asynchronously while visual tokens stream continuously under strict GPU-memory and query-time latency budgets. A key challenge is delayed query: decisive cues may appear briefly, yet many subsequent updates occur before the query arrives, increasing the risk that those cues are evicted or diluted under bounded memory. We propose ProtoKV, a constant-footprint SVU memory that represents far history as a fixed-capacity summary state rather than retaining token instances. ProtoKV keeps an exact near-window KV cache and aggregates older content into a semantic-spatial prototype bank with residual statistics. At query time, each prototype is exposed through a bounded pseudo-token interface that is drop-in compatible with standard attention. Under matched budgets and comparable query-time cost, ProtoKV improves accuracy by up to 12.5 points over token-retention baselines on SVU benchmarks in the long-delay regime, with gains that grow as query delay increases.

## 1. 论文的核心问题与整体含义

**研究动机**  
流式视频理解（Streaming Video Understanding, SVU）系统需要在连续视频流上实时推理，并响应异步到达的查询。一个关键挑战是**延迟查询**：决定性视觉线索可能短暂出现（如一个状态变化），但在查询到达之前，系统会继续吸收大量后续帧更新。在固定GPU内存预算下，这些线索容易被驱逐或稀释，尤其当延迟较大时。现有方法（如滑动窗口、token保留）在长延迟下性能急剧下降。

**整体含义**  
ProtoKV旨在解决“后证据更新压力”（post-evidence update pressure）——即确定性的线索必须经历多次有损压缩/驱逐操作才能存活到查询时刻。论文提出一种**恒定内存占用**的摘要状态记忆，将远历史表征为固定容量的原型库，而非保留具体token实例，从而在长延迟下更稳定地保持关键信息。

## 2. 方法论

**核心思想**  
ProtoKV采用**两层在线状态**：
- **近窗口**：精确保存最近W个token的KV对，提供细粒度的局部信息。
- **远记忆**：固定容量（Kmax个原型）的**原型库**，每个原型聚合多个驱逐token的摘要信息，包括中心(ck, pk)、质量nk、残差统计Rk（使用乘积量化直方图）、空间统计(μk, Σk)和最近更新时间τk。

**关键技术细节**  
1. **连续感知原型分配**：当token被驱逐出近窗口时，通过组合三个项的代价函数分配到原型：
   - key相似度（负余弦）
   - 空间连续性（Mahalanobis距离，考虑物体轨迹）
   - 空闲惩罚（抑制长时间未更新原型）
2. **原型更新**：使用EMA更新中心、空间状态，并累加残差到PQ直方图。
3. **原型维护**：包括空闲老化（质量衰减）、冗余合并、质量为零时回收重用。
4. **查询时伪token合成**：对每个原型，从其PQ直方图中通过束搜索解码出S个残差模式，叠加中心形成伪KV对。所有伪token共享该原型的RoPE位置（最近吸收token的时间戳），并添加**质量感知偏置**（log nk）到注意力logit，模拟多重token的影响。
5. **固定长度上下文**：近窗口W个token + Kmax × S个伪token，查询时间注意力成本恒定。

**算法流程**（文字描述）  
- 流式更新：每帧token先进入近窗口，当超过W时驱逐最旧token，执行分配、更新、维护（算法1、2）。
- 查询时：读取所有原型，为每个解码S个伪token，拼接近窗口KV，加入质量偏置，执行标准注意力（算法3、4）。

## 6. 主要结论与发现

- ProtoKV在**所有SVU基准**上优于SWA和InfiniPot-V，且在**长延迟下优势更大**：在RVS-Movie上最高超过InfiniPot-V +12.5pp，超过SWA +20.4pp。
- **退化曲线更平缓**：随着延迟增加，准确率下降幅度远小于对比方法。
- **组件贡献**：远记忆、残差统计、质量偏置、连续感知分配均对长延迟鲁棒性有显著正面影响；去除其中任何一个都会导致性能下降。
- **查询时间效率**：ProtoKV的TTFT与预算基线相当，比卸载/检索方法快26%。
- **离线任务**：在VideoMME和MLVU上，ProtoKV在紧凑预算下也能达到竞争或更好的结果。
- **弱点**：在需要**计数**或**区分多个视觉相似事件**的任务（如Action Count）上，由于多个相似事件被合并到同一原型，计数能力受限。

## 7. 优点

1. **新颖的摘要状态设计**：用固定容量原型代替token保留，从根本上减轻后证据更新压力，使关键信息不易被逐出。
2. **无需模型修改与训练**：伪token接口与标准注意力完全兼容，可直接用于预训练VLM。
3. **恒定查询时间成本**：上下文长度W + Kmax·S固定，延迟可预测。
4. **系统级优化**：连续感知分配结合空间和语义信息，减少原型碎片；质量感知偏置自然模拟多token效果。
5. **实验严谨**：采用严格的预算匹配、延迟协议、交集子集评估，消融和敏感性分析全面。
6. **应用广泛性**：不仅适用于SVU，也适用于离线视频理解（表3），扩展性强。

## 8. 不足与局限

1. **计数任务表现弱**：视觉相似事件易被合并到同一原型，导致无法区分重复次数（附录E案例4），这是摘要状态的固有限制。
2. **近似延迟协议**：使用数据集定义的查询时间t0代替真实证据时间te，仅保留回顾性查询，可能丢失部分任务类型（如实时理解）。
3. **固定伪token数S和原型容量Kmax**：虽然附录探讨了动态分配，但默认固定，可能无法自适应不同视频的动态性。
4. **仅测试7B骨干**：未在更大模型（如Llama-3系列大模型）或其他视觉编码器上验证泛化性。
5. **超参数较多**：虽然敏感性较低（±0.9%），但默认配置（如λsp, λidle, α, β等）需手动设定，不同场景可能需要微调。
6. **未考虑文本Token交互**：当前只处理视觉token，查询中的文本指令不作为记忆的一部分，可能限制复杂推理。
7. **缺乏真实流式部署验证**：实验在离线基准的模拟流式设置下进行，未在真实在线系统中测试延迟波动和容错。
