## 摘要
云端托管的的大规模多模态模型（LMM）能够为车联网（V2X）系统提供强大的开放词汇感知能力，但直接将全分辨率帧从边缘节点传输至云端会导致严重的通信开销和云端预填充延迟。我们提出CABLE，一种用于边缘-云端感知的云辅助带宽高效LMM编码框架。CABLE利用自运动补偿在边缘端传播先前的云分割掩码，通过残差运动线索进行细化，并借助走廊包络整合分离的区域，形成稳健的感兴趣区域（ROI）。仅上传ROI掩码后的图像，同时将云端分割输出作为下一帧的先验反馈，形成掩码-ROI-LMM的反馈循环。在五个数据集（nuScenes、WOD-ZB、Waymo、KITTI和CADC）上的实验表明，该方法在显著节省通信开销的同时保持了较好的感知性能，实现了73%–87%的ROI像素覆盖减少，并且相比全帧推理，预填充速度预计提升5–8倍，仅在检测质量上略有折衷。

## Abstract
Cloud-hosted large multimodal models (LMMs) can provide strong open-vocabulary perception for Vehicle-to-Everything systems, but naively transmitting full-resolution frames from edge to cloud causes severe communication overhead and high cloud-side prefill latency. We present CABLE, a cloud-assisted bandwidth-efficient LMM-based encoding framework for edge-cloud perception. CABLE propagates the previous cloud segmentation mask on the edge using ego-motion compensation, refines it with residual-motion cues, and consolidates disconnected regions via a corridor envelope to form a robust region of interest (ROI). Only ROI-masked images are uploaded, while the cloud segmentation output is fed back as the prior for the next frame, forming a mask-to-ROI-to-LMM feedback loop. Experiments on five datasets (nuScenes, WOD-ZB, Waymo, KITTI, and CADC) show consistent communication savings while largely preserving perception, achieving $73$--$87\%$ ROI pixel-coverage reduction with $5$--$8\times$ estimated LMM prefill speedup at a modest detection-quality trade-off relative to full-frame inference.

## 1. 论文的核心问题与整体含义（研究动机与背景）

- **核心问题**：在车联网（V2X）系统中，云端大型多模态模型（LMM）能提供强大的开放词汇感知能力。然而，将边缘设备采集的全分辨率视频帧直接上传到云端，会造成**严重的通信瓶颈**（高带宽消耗）和**云端计算瓶颈**（LMM处理长视觉token序列时，预填充阶段的计算复杂度随token数量呈二次增长）。
- **研究动机**：安全关键动态物体（车辆、行人、骑行者）通常只占据图像的一小部分区域，大部分像素为缓慢变化的背景。因此，仅传输并处理包含这些物体的**感兴趣区域（ROI）**，可以显著降低负载而不损失关键感知信息。现有ROI选择方法（基于检测或基于运动）存在封闭集标签限制、易受自运动干扰、压缩效率低或误报率高等缺陷。
- **整体含义**：本文提出了CABLE，一个**闭环反馈式**的边缘-云端感知框架，通过高效ROI生成和选择性传输，旨在在不严重降低感知性能的前提下，大幅减少上行带宽需求并加速云端LMM推理。

## 2. 论文提出的方法论

### 核心思想
CABLE构建了一个**“掩码 → ROI → LMM → 掩码”的跨帧反馈循环**：边缘设备接收上一帧的云端分割掩码，利用轻量级操作预测当前帧的ROI，仅上传ROI掩码后的图像；云端LMM在紧凑的ROI图像上进行推理，产生语义分割掩码，并将其反馈给边缘设备，作为下一帧ROI生成的先验。

### 关键技术细节与流程

1.  **云端关键帧初始化与刷新**：
    -   **初始化**：对于第一帧（无先验），上传全帧图像，LMM进行开放词汇分割，生成初始掩码 `M0`。
    -   **刷新触发**：边缘设备持续监控ROI质量和掩码一致性。若当前帧`ROI覆盖率<τmin`或`当前ROI与上一帧云端掩码的交并比<τiou`，则触发全帧刷新上传，以应对严重漂移。

2.  **边缘端几何掩码传播**：
    -   **自运动补偿（单应性变换）**：利用相邻帧间的自车速度 `(vx, vy)` 和相机内参 `(fx, fy)`，在纯平移假设下计算单应性矩阵 `Hk`，将上一帧的云端掩码 `Mk-1` 和图像 `Ik-1` 扭曲到当前帧视角，得到 `M_head(k-1)` 和 `I_head(k-1)`。
    -   **残差运动能量检测**：计算经过自运动补偿后的当前帧与上一帧扭曲图像的灰度差 `Ek`，通过阈值 `τe` 生成运动检测图 `Dk`，以捕捉独立运动的新物体。
    -   **自适应缓冲膨胀**：为防止掩码因累积扭曲误差而缩小，对扭曲后的掩码进行膨胀操作，膨胀核大小 `bk` 根据自车速度自适应调整。
    -   **ROI融合**：将扭曲掩码 `M_head(k-1)` 与经过膨胀缓冲门控的运动能量图 `M+_head(k-1)∩Dk` 进行并集，得到初步ROI `R_raw_k`。

3.  **走廊包络合并**：
    -   将可能分散的ROI斑点合并为一个**连续的驾驶走廊**。算法提取ROI每列的最上和最下像素边界，经平滑和扩展后，形成一个完整的多边形掩码 `Rk`。此举保留了物体间的空间上下文，有利于LMM理解。

4.  **背景跳过传输与云端推理**：
    -   边缘设备将ROI外的像素置零，生成背景跳过图像 `Ĩk` 并上传。
    -   云端LMM对 `Ĩk` 进行分割，输出掩码 `Mk`（限制在ROI区域内 `Mk = F(Ĩk, p) ∩ Rk`）。

5.  **跨帧掩码反馈**：
    -   云端掩码 `Mk` 被传回边缘设备，替换先前的掩码状态，形成闭环，使得系统能够持续适应动态场景。

### 公式或算法流程
-   **优化目标**：最小化所有帧的平均ROI覆盖率，同时确保感知质量 `Q(Mk, Gk)` 不低于阈值 `γ`。
-   **算法流程**：见论文Algorithm 1，核心步骤为：1) 全帧初始化；2) 每帧自车补偿和残差运动检测；3) 自适应当膨胀和ROI融合；4) 走廊包络合并；5) 根据触发条件选择上传ROI或全帧；6) 云端推理与掩码反馈。

## 8. 不足与局限

-   **冷启动与漂移风险**：系统严重依赖初始全帧推理。如果在第一帧或刷新帧时反馈的掩码质量差，或自运动补偿模型在**大旋转（急转弯）** 时累积误差，可能导致后续ROI持续漂移。虽然有关键帧刷新机制，但其触发条件`τmin`和`τiou`的阈值设置敏感性待评估。
-   **感知评估的局限性**：
    -   **宽松的“物体识别率”指标**：仅5%的重叠即算识别，可能高估了对部分遮挡物体的感知能力。其指标“检测保持率/F1”虽更严格，但未能评估分割掩码的**精确像素级**质量。
    -   **下游检测器依赖**：对检测性能的评估依赖于RT-DETR。若使用其他检测器，结果可能会有差异。
-   **未验证实际操作性能**：论文中的带宽节省是基于**像素覆盖率**的估计，而非实际无线链路上的编码比特率。预填充加速也是基于`n²`复杂度的**分析估计**。**缺乏在真实V2X链路上的端到端延迟和码流测试**，这是其部署实用性的关键。
-   **基准对比不完整**：未与现有的一些先进边缘-云协同推理方案（如特征压缩、ROI感知编码、边缘检测器/分割器的基线方案）进行直接对比。
-   **自运动模型简化**：纯平移假设在处理弯道路口时存在局限，虽然文中声称通过残差运动和刷新机制缓解了问题，但其对整体性能的具体影响边界未明确。
