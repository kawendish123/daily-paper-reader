## 摘要
在边缘平台上部署视觉Transformer（ViT）模型仍然具有挑战性，因为其计算需求高，且现代混合ViT模型在架构上具有异构性，同时包含全连接层和卷积层。这种异构性导致张量形状的显著变化，需要灵活高效的基于FPGA的加速。在本文中，我们提出FlexViT，一种可重构的FPGA加速器，用于在资源受限的边缘设备上进行高效的ViT推理。基于SECDA-TFLite框架，FlexViT采用软硬件协同设计方法，通过运行时im2col变换将全连接层和卷积层映射到统一的高吞吐量INT8 GEMM引擎上。为了高效支持多样化的层配置，我们提出了一种双模式数据流，通过在运行时重新配置计算阵列，在输入重利用和权重重利用之间动态切换。我们进一步引入了一种深度优先的平铺策略，单次遍历完成累加，消除了片外部分和传输，降低了内存带宽需求。我们在PYNQ-Z2 FPGA上实现了FlexViT，并在代表性ViT模型集上进行了评估。与纯CPU执行相比，FlexViT在加速器执行的层上实现了最高2.74倍的加速，转化为最高1.40倍的端到端加速。代码已在以下链接开源：https://github.com/gicLAB/FlexViT

## Abstract
Deploying Vision Transformer (ViT) models on edge platforms remains challenging due to their high computational demands and the architectural heterogeneity of modern hybrid ViT models, which incorporate both fully connected and convolutional layers. This heterogeneity leads to significant variation in tensor shapes, requiring flexible and efficient FPGA-based acceleration. In this paper, we present FlexViT, a reconfigurable FPGA accelerator for efficient ViT inference on resource-constrained edge devices. Built on the SECDA-TFLite framework, FlexViT employs a hardware-software co-design approach that maps both fully connected and convolutional layers onto a unified high-throughput INT8 GEMM engine using a runtime im2col transformation. To efficiently support diverse layer configurations, we propose a dual-mode dataflow that dynamically switches between input and weight reuse by reconfiguring the compute array at runtime. We further introduce a depth-first tiling strategy that completes accumulation in a single pass, eliminating off-chip partial-sum transfers and reducing memory bandwidth requirements. We implement FlexViT on a PYNQ-Z2 FPGA and evaluate it across a representative set of ViT models. FlexViT achieves up to 2.74x speedup on accelerator-executed layers, translating into up to 1.40x end-to-end speedup compared to CPU-only execution. The code is available at: https://github.com/gicLAB/FlexViT

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：在现代边缘设备上高效部署视觉Transformer（ViT）面临两大挑战：一是ViT模型计算量巨大，对资源受限的FPGA构成压力；二是现代混合ViT（如MobileViT、EfficientViT）同时包含全连接（FC）层和卷积（CONV）层，导致张量形状剧烈变化（例如序列长度从12,000降至49，通道宽度从16增至1,536），传统单数据流加速器难以适应这种异构性，造成硬件利用率低下。
- **研究动机**：现有FPGA加速器通常针对FC主导的Transformer或CONV主导的CNN分别优化，缺乏统一支持标准ViT和混合ViT的灵活设计。作者旨在填补这一空白，提出一种可重构、统一的FPGA加速器，在资源极度受限的边缘FPGA（如PYNQ-Z2）上实现高效推理。
- **整体含义**：通过软硬件协同设计，将异构层映射到同一GEMM引擎，并动态配置数据重用模式，从而在不修改模型的前提下加速多种ViT架构，为边缘设备提供实用的AI推理方案。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：采用软硬件协同设计，基于SECDA-TFLite框架构建FPGA加速器。将FC层和CONV层通过运行时的**im2col变换**统一转化为矩阵乘法（GEMM），然后在单一的INT8 GEMM引擎上执行。通过**双模式数据流**（Input-Broadcast和Weight-Broadcast）和**深度优先平铺（depth-first tiling）** 来应对层维度的多样性和资源限制。
- **关键技术细节**：
  - **统一GEMM引擎**：所有FC和CONV层经im2col后变成(N, M, K)矩阵，加速器仅需处理GEMM操作，非核心运算（Softmax、LayerNorm等）保留在CPU上执行，避免硬件过度专用化。
  - **双模式数据流**：
    - **Input-Broadcast模式**：当输出宽度足够大（$\tilde{M} \ge C \times T_M$）时，外循环遍历N，内循环遍历M。输入瓦片广播给所有核心，权重点分给不同核心，最大化激活值重用。
    - **Weight-Broadcast模式**：当层太窄（如CONV层）时，外循环遍历M，内循环遍历N。权重点广播，输入瓦片分发，最大化权重重用。
    - 模式选择由主机驱动根据层类型（FC固定规则；CONV使用DMA传输估算）在运行时动态决定（Algorithm 1）。
  - **深度优先平铺**：每个核心计算64×64输出瓦片，片上输入和权重缓冲区深度设为K=1024，足以覆盖4/5模型的所有层（EfficientViT最后一分类层除外），从而**单次完成全部累加**，避免片外部分和读写，显著降低内存带宽需求。
  - **硬件架构**：包含调度器、三个读取单元（输入、权重、偏置）、三个并行GEMM核心、后处理单元（PPU）。每个核心内部采用SIMD向量引擎（Kf=16），内循环沿K维度流水线执行INT8 MAC，中间累加保存在本地寄存器（输出固定数据流）。PPU根据层类型（FC/CONV）选择不同的反量化方式（逐张量/逐通道）。
  - **资源映射**：使用LUT+DSP混合的MAC单元（低8位用LUT，高8位用DSP），提高MAC密度。缓冲区采用循环分区，避免并行访问冲突。
- **算法流程（文字描述）**：对于每个offloaded层，主机根据层类型和维度的DMA估算选择数据流模式 → 调度器读取配置包 → 按所选模式遍历N/M/K瓦片 → 读取单元预取数据（与计算重叠） → GEMM核心执行流水线MAC → PPU完成偏置加法和反量化 → 输出8-bit结果送回主机。

## 6. 论文的主要结论与发现

- **加速性能**：在PYNQ-Z2上，FlexViT对offloaded FC/CONV层实现最高2.74×层级别加速；端到端延迟提升1.24×–1.40×。

## 7. 优点

- **统一性**：将FC和CONV统一映射到GEMM，支持标准ViT和混合ViT，无需专用注意力或卷积引擎，设计简洁。
- **灵活性**：运行时动态切换数据流模式，适应不同形状张量，提高处理元素利用率。Algorithm 1中通过规则和DMA估算选择，实现自动调优。
- **资源高效**：深度优先平铺结合大深度缓冲区（TK=1024），消除片外部分和，节省带宽并简化控制。在极资源受限的PYNQ-Z2上实现了可接受的性能。
- **软硬协同**：CPU负责非核心操作和im2col转换，FPGA专注GEMM，避免硬件过度复杂；使用SECDA-TFLite框架实现快速开发和实际端到端评估。
- **开源可复现**：代码公开在GitHub，详述架构参数，便于复现和扩展。

## 8. 不足与局限

- **性能瓶颈转移**：混合ViT中“其他”操作（Softmax、LayerNorm、reshape等）占比大，成为系统瓶颈，限制了端到端加速的上限（Amdahl定律）。未尝试将这些操作也硬件化。
- **缺乏深度消融**：未定量分析双模式数据流相比于静态模式的收益、不同平铺尺寸/核心数的权衡等，使设计决策的合理性缺乏数据支撑。
- **平台限制**：仅验证在PYNQ-Z2（Zynq-7020）上，结论可能不直接迁移到更高端FPGA。论文未讨论在更大FPGA上加速器架构的可扩展性。
- **任务单一**：仅评估图像分类，未在检测/分割场景测试，而混合ViT在这些任务中应用广泛。
- **im2col开销**：im2col在CPU执行，虽避免了硬件复杂度，但增加了CPU负载和内存带宽压力。论文未单独报告im2col的开销。

- **能量测量精度**：使用低成本USB功率计，精度可能有限，且未分离静态功耗影响。
