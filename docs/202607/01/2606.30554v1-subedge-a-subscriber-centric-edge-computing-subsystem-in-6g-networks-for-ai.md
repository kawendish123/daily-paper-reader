## 摘要
超越传统连接，6G被设想将移动网络转变为分布式结构，提供原生集成的通信、计算和智能服务。AI原生终端（如机器人、自动驾驶车辆和智能眼镜）需要来自个性化、制造商特定模型的实时推理，这些模型既无法在终端上执行，也无法跨订阅者共享，这使得每订阅者边缘计算成为每订阅者连接的必要补充。现有的面向AI的网络架构通过共享部署为应用提供商提供计算资源，未解决每订阅者的资源供应问题。本文提出SubEdge，这是一个面向AI的网络子系统，以每订阅者为基础提供集成通信和计算资源，确保两个维度的耦合迁移以在移动过程中维持服务连续性。SubEdge贡献了计算上下文——一种每订阅者数据结构，将订阅永久标识符与其推理容器、边缘节点和服务权限绑定——以及一种移动事件驱动机制，当服务小区发生变化时，同时迁移订阅者的计算实例及其流量路由策略。SubEdge作为应用功能运行于现有网络开放功能API之上，无需对3GPP核心进行修改。在真实测试平台上的实验评估表明，SubEdge的移动驱动的联合通信与计算迁移在六次移动事件中将第95百分位延迟从22.9毫秒降低到12.2毫秒，零丢包；在端到端30帧/秒的推理工作负载中维持99.92%的帧交付；在多达50个同时迁移订阅者的批次中成功完成1560次迁移操作，成功率为100%。

## Abstract
Beyond traditional connectivity, 6G is envisioned to transform mobile networks into a distributed fabric that provides native integrated communication, computing, and intelligence services. AI-native terminals (e.g., robots, autonomous vehicles, and smart glasses) require real-time inference from individualised, manufacturer-specific models that cannot be executed on-board nor shared across subscribers, making per-subscriber edge compute the necessary complement to per-subscriber connectivity. Existing Network for AI (Net4AI) architectures provision compute for application providers through shared deployments and do not address per-subscriber provisioning. This paper proposes SubEdge, a Net4AI subsystem that provisions integrated communication and compute resources on a per-subscriber basis, ensuring the coupled migration of both dimensions to maintain service continuity during mobility. SubEdge contributes the computing context--a per-subscriber data structure binding a Subscription Permanent Identifier (SUPI) to its inference container, edge node, and service entitlement--and a mobility-event-driven mechanism that simultaneously migrates the subscriber's compute instance and its traffic-routing policy when the serving cell changes. SubEdge operates as an Application Function over existing Network Exposure Function (NEF) APIs with zero 3GPP core modifications. Experimental evaluation on a real-world testbed shows that SubEdge's mobility-driven joint communication-and-compute migration reduces 95th-percentile latency from 22.9 ms to 12.2 ms with zero packet loss across six mobility events, sustains 99.92% frame delivery for an end-to-end 30 fps inference workload, and completes 1,560 migration operations across batches of up to 50 simultaneously migrating subscribers with 100% success.

# 论文中文总结

## 1. 核心问题与整体含义（研究动机和背景）
- **背景**：6G 愿景将移动网络从单纯的连接基础设施转变为原生融合通信、计算和智能的分布式结构。AI 原生终端（如机器人、自动驾驶车辆、智能眼镜）依赖制造商定制的个性化 AI 模型进行实时推理，这些模型无法在终端本地执行（受限于功耗、重量和 GPU 成本），也无法跨订阅者共享。
- **核心问题**：现有 Net4AI 架构（如 MEC、EDGEAPP、In-Network Computing、网络切片、AI Sessions）均面向应用程序提供商设计，以共享方式部署计算资源，未提供每订阅者（per-subscriber）级别的专用计算供应。没有一种架构将边缘计算资源绑定到订阅者永久标识符（SUPI），也未将 3GPP 订阅者移动性事件作为计算生命周期触发器。AI 终端用户需要“每订阅者连接 + 每订阅者计算”，但现有方案不满足这一需求。
- **意义**：SubEdge 填补了这一空白，使移动运营商能够像提供连接一样，为每个 AI 终端订阅者提供专用推理计算资源，并在移动过程中保持连续服务，从而为 6G 原生 AI 服务开启新范式。

## 2. 方法论：核心思想、关键技术细节
- **核心思想**：以订阅者为中心，将每个订阅者的推理容器视为一级网络对象，绑定到其 SUPI；将计算供应与移动性管理不可分割地结合起来——当终端移动时，同时迁移计算实例（compute migration）和流量路由策略（communication migration）。
- **关键技术细节**：
  - **计算上下文（Computing Context）**：每订阅者的数据结构，包含 SUPI、容器实例、边缘节点、工作负载引用、执行状态、服务等级等。它是“订阅者计算”层面的基本单元，类似于 PDU session 之于连接。
  - **架构组件**：共六个内部组件，全部通过标准 NEF API 与 5GC 交互，无需修改任何核心网功能。
    - Computing Context Manager (CCM)：中心编排器，维护计算上下文，与 NEF 接口。
    - Subscriber Profile Store (SPS)：存储每订阅者的服务等级、GPU 分配、SLA、执行模式（hot/warm/cold）。
    - Placement Engine (PE)：基于订阅者服务小区和资源需求，选择最优边缘节点；移动时选择性重新评估，若当前节点仍在 SLA 内则不触发迁移，避免容器抖动。
    - Container Repository (CR)：存储和分发订阅者拥有的 OCI 容器镜像，支持预缓存以加速迁移。
    - Container Orchestrator (CO)：在边缘节点上执行容器生命周期（拉取、创建、健康检查、make-before-break 迁移、拆除）。
    - Edge Node Registry (ENR)：维护边缘节点状态（GPU 可用性、小区到节点映射、健康状态）。
  - **移动性驱动的联合迁移机制**：
    1. AMF 通过 Nnef_EventExposure 报告服务小区变化。
    2. CCM 调用 PE 重新评估位置；若需迁移，则进入两阶段过程：
       - 计算迁移阶段：CO 在目标边缘节点上启动新容器（从本地 CR 缓存拉取预存镜像）。
       - 通信迁移阶段：新容器健康后，CCM 发起一条 Nnef_TrafficInfluence PUT 请求，更新流量路由策略，将订阅者流量导向新节点。随后停止源容器。
    3. 终端无感知，因使用虚拟 IP 地址，切换过程不中断。
  - **部署方式**：作为 Application Function (AF) 运行于 NEF 之上，继承 IP 多媒体子系统 (IMS) 的“不修改核心网”模式。

## 6. 主要结论与发现
- SubEdge 的移动性驱动的联合通信与计算迁移：
  - **链路层**：第 95 百分位 RTT 从 22.9 ms（静态 Node A）和 22.8 ms（静态 Node B）降至 12.2 ms；88% 样本低于 10 ms（静态 A 仅 41%，静态 B 仅 50%）。零丢包（609/609 次 ICMP 响应）。
  - **应用层**：30 fps 推理工作负载下，17,985 / 18,000 帧成功交付（99.92%），丢失的 15 帧全部分布在 6 次迁移的收敛区间内（每次迁移损失不超过 2-3 帧），稳定运行期间无帧丢失。
  - **控制面**：1,560 次并发迁移操作全部成功（HTTP 200），每订阅者 PUT 延迟随并发数线性增长（斜率 7.4 ms，R²=0.999），但在生产环境中可通过 NEF 水平扩展消除瓶颈。
- 结论：SubEdge 实现了零核心网修改的每订阅者计算集成，证明了该范式在现有 5G 基础设施上的可行性和性能增益。
