## 摘要
在在线流视频理解中，视频流持续到达，查询可能随时发出。由于流帧无限增长，系统必须持续压缩并保留观察到的视频前缀中的信息，而未来帧和未来查询仍未知。核心挑战在于决定保留哪些信息以及如何组织维护的历史：随着历史随流增长，内存成本增加，大量冗余视觉细节被保留，而后续查询往往依赖于特定实体、动作及其时序变化。为应对这一挑战，我们引入了FOLIO，一种无需训练的聚焦语义记忆系统，以更高细节记录流中的重要部分，同时保持周围上下文紧凑。当流到达时，FOLIO在片段级别更新记忆，由动态聚焦状态引导，结合短期视觉缓冲和围绕观察到的实体组织的长期语义记忆，并链接到视觉证据缓存。在查询时，轻量级混合检索将结构化记忆上的直接匹配与语义查询扩展相结合。FOLIO达到了最先进的性能，在OVO-Bench上使用Qwen3-VL-8B达到82.0/69.1的感知/反向准确率，在StreamingBench上达到74.5的整体准确率，同时通过为聚焦实体保留详细记录并紧凑存储周围上下文，大幅降低了维护流内存的成本。

## Abstract
In online streaming video understanding, a video stream continues to arrive and queries may be issued at any time. Because streaming frames grow without bound, the system must continuously compress and retain information from the observed video prefix while future frames and future queries remain unknown. The core challenge is deciding what information to retain and how to organize the maintained history: as this history grows with the stream, memory cost increases and many redundant visual details are retained, whereas later queries often depend on specific entities, actions, and their temporal changes. To address this challenge, we introduce FOLIO, a training-free focused semantic memory system that records important parts of the stream in higher detail while keeping surrounding context compact. As the stream arrives, FOLIO updates memory at the segment level, guided by a dynamic focus state, combining a short-term visual buffer with a long-term semantic memory organized around observed entities and linked to a visual-evidence cache. At query time, lightweight hybrid retrieval combines direct matching over the structured memory with semantic query expansion. FOLIO achieves state-of-the-art performance, reaching 82.0/69.1 Perception/Backward accuracy on OVO-Bench with Qwen3-VL-8B and 74.5 overall accuracy on StreamingBench, while substantially reducing the cost of maintaining streaming memory by reserving detailed records for focused entities and storing surrounding context compactly.

## 1. 核心问题与整体含义（研究动机和背景）

- **研究动机**：在线流视频理解场景中，视频帧持续到达，用户可以在任意时刻发出查询。系统必须仅利用已观察到的视频前缀进行回答，而未来帧和未来查询未知。由于流帧无限增长，如何高效压缩和组织历史信息成为核心挑战——既要避免存储无限增长的冗余视觉细节，又要保证后续查询（常依赖特定实体、动作及其时序变化）能够被准确回答。
- **整体含义**：现有方法（如窗口缓存、token/KV压缩、场景/事件记忆等）要么记忆随流增长导致成本高，要么难以按语义检索实体，要么在长时跨度和多轮交互中失效。FOLIO提出一种无需训练的聚焦语义记忆系统，通过动态焦点状态决定保留哪些实体的高细节，同时保持其余上下文紧凑，在准确率和记忆成本之间取得更好平衡。

## 2. 方法论

### 核心思想
- 在流视频处理中，按固定时长（如8秒）将视频切分为连续片段（segment），每个片段完成后触发记忆写入。
- 维护一个**动态焦点状态**（focus state），为每个观测到的实体/动作计算焦点分数，分数高的实体在写入时获得更详细的记录（状态、位置、关系、动作链等），分数低的则仅写入紧凑记录。
- 记忆结构为**混合记忆**：
  - **短期视觉缓冲**（short-term visual buffer）：保留最近帧的原始视觉信息，用于回答当前状态查询。
  - **长期语义记忆**（long-term semantic memory）：以实体为中心的结构化存储，记录实体名称、别名、类别、属性、位置链、动作链、关系以及链接到视觉证据缓存的帧索引。
  - **视觉证据缓存**（visual-evidence cache）：存储每个片段中选择的关键帧，按时间索引，可被实体记录引用恢复。
- **焦点状态更新公式**：  
  `p_i(o) = clip[0,1](γ p_{i-1}(o) + α^T φ^+_i(o) - β^T φ^-_i(o))`  
  其中正特征包含可见性、重现、状态变化、事件参与、多轮交互相关性等；负特征包含消失、静态背景等。多轮交互中，前序问题的匹配实体可获得焦点提升。
- **查询时混合检索**：先对查询和选项进行语义解析，然后直接匹配结构化记忆中的实体名、别名、类别等，若无足够匹配则使用VLM进行语义查询扩展（提出相关实体名再匹配）。最终将检索到的结构化记录、短期视觉缓冲和可选的缓存关键帧一并送入回答VLM生成答案。

### 关键技术细节
- 自适应关键帧选择：每个片段选取边界帧、中间帧和帧间变化最大的探针帧，若变化小且无焦点实体风险则仅保留边界帧。
- 写入级别：焦点（focus）、支持（support）、上下文（context）、丢弃（drop），由焦点分数决定。
- 实体合并：基于规则（名称、别名、类别、属性）避免将不同实体误合并，并利用区分性修饰符（如颜色）抑制弱匹配。
- 多轮焦点更新：解析前序问题的目标、锚点和选项，匹配的实体获得焦点提升，未匹配的放入待定集，后续观测到后再提升。

## 3. 实验设计

### 数据集与基准
- **OVO-Bench**：单轮流问答基准，包含感知（Perception）和反向追踪（Backward）两大类共9个子任务（OCR、ACR、ATR、STU、FPD、OJR、EPM、ASI、HLD），共1468个问题，512个视频。
- **StreamingBench**：多轮流交互基准，包含实时视觉理解（Realtime）、全源理解（OmniSource）、顺序问答（SQA）、主动输出（Proactive）四个大类，共900视频、4500问答对。
- **StreamBench**（补充实验）：开放域多轮流问答，6个子集（SF、OS、SM、LM、CI、KG），评价采用LLM-as-judge语义相似度。

### 对比方法
- 单轮：Gemini 1.5 Pro, GPT-4o, LLaVA-Video-7B, LLaVA-OneVision-7B, Qwen2-VL（7B/72B）, Flash-VStream-7B, VideoLLM-online-8B, StreamChat‡, Dispider, Qwen2.5-VL-7B + OASIS, Qwen3-VL-8B + OASIS等。
- 多轮：VideoLLM-online-8B, Dispider-7B, StreamAgent-7B, Think-While-Watching (Qwen3-VL-8B)等。
- 消融实验包含：去除关键组件（窗口、焦点控制器、结构化记忆、自适应视觉、交互焦点）以及查询时证据源消融（S/O/B组合）。

### 实验条件
- 严格在线流协议：每个查询仅使用观察前缀、已构建的记忆和之前对话历史，不用未来帧，选项仅查询时刻提供。
- 模型：VLM使用Qwen2.5-VL-7B和Qwen3-VL-8B作为主干。
- 推理框架：vLLM，OpenAI兼容多模态接口，24K最大token长度。
- 硬件：NVIDIA RTX 6000 Ada Generation GPU（48GB显存，960GB/s带宽）。

## 6. 主要结论与发现

- FOLIO在OVO-Bench上使用Qwen3-VL-8B达到感知82.0%、反向69.1%，显著超过OASIS（+4.6～+11.9点）；在StreamingBench上整体74.5%准确率，优于最强基线Think-While-Watching（58.82%）。
- 长期语义记忆最受益于反向追踪和幻觉检测任务（HLD），短期视觉缓冲对当前状态至关重要。
- 焦点控制与自适应关键帧选择可减少约33%的写入输入token、32%的输出记录，同时提升准确率4.4点。
- 块长度最佳为8秒，过长（32秒）掉6点，过短（2秒）成本增加但无提升。
- 失败分析显示：“已写但未检索”错误极少，主要瓶颈在于检索到的证据仍不足以区分答案（78.4%在StreamingBench、60%在OVO-Bench），以及记忆粒度不足导致细粒度状态错失。
- 多轮交互中，焦点记忆更新比仅将历史查询提供给答案生成器更有效。

## 7. 优点

- **无需训练**：完全基于预训练VLM，无需领域微调，易于部署和扩展。
- **聚焦注意力**：动态焦点状态实现了选择性记忆，在压缩冗余信息的同时保留关键实体细节，平衡了内存与准确率。
- **实体为中心的长期记忆**：不同于帧/事件/缓存，以稳定实体标识为核心，支持跨片段、跨场景的持久跟踪，便于按语义检索。
- **高效的混合检索**：结构化直接匹配+轻量VLM语义扩展，避免重检索或全量帧搜索。
- **多轮交互适配**：通过焦点提升机制将前序查询信息反馈到后续记忆写入，增强对对话历史的支持。
- **充分消融与诊断**：包含详细的组件、证据、块长度、长时记忆、多轮焦点等消融，以及失败模式分析，提供了清晰的设计验证和后续方向。

## 8. 不足与局限

- **记忆粒度有限**：对于短暂社交动作（如碰拳vs击掌）、细粒度OCR分数变化等，当前写入可能过于粗粒度，导致区分不足。
- **固定块边界**：块长度固定为8秒，不适用于需要事件触发边界的场景（如快速场景切换）。
- **写入延迟瓶颈**：单卡上每段写入需5.88–7.68秒，虽然符合流式要求，但若需更实时响应或高帧率，可能仍需加速（如批处理、更轻量writer）。
- **实验覆盖局限**：OVO-Bench和StreamingBench虽较全面，但未涵盖户外长时间实时场景（如自动驾驶）；主动输出任务仅做完整性报告，并非FOLIO核心优势。
- **对领域特定信息的支持弱**：如球赛比分变化、体育动作识别等需要更丰富的记忆字段（如计分板状态跟踪），当前通用schema可能不够。
- **依赖VLM质量**：写入和回答均依赖主干VLM的视觉理解能力，若VLM本身在OCR或动作识别上存在缺陷，FOLIO难以完全弥补。
- **幻觉检测仍有挑战**：在HLD任务中，当检索到相关实体但证据不足以直接回答时，模型倾向于过度推断而非正确拒绝回答。
